Roteador manual com captura de parâmetros

🎯 Objetivo

Antes de escrever qualquer endpoint com if (url.pathname === ...), construir um roteador de trinta linhas que casa método e padrão de caminho, e captura parâmetros como o :q da busca. Ele vai sobreviver até a fase 45.

👨‍💻 O que você digita

Sem roteador, cada endpoint vira um if no fetch — e os que têm parâmetro ficam impossíveis: /livros/9780321125217, /livros/Limpo e /livros/Austen são caminhos diferentes que precisam cair no mesmo handler. Comparar string com === não resolve.

São três peças: o tipo Route, a função match e o laço dentro do fetch.

A rota
typescript
trecho ilustrativo
type Route = { method: string; pattern: string; handler: Handler };

Método, padrão e o que fazer. O pattern é a única sintaxe que estamos inventando: segmentos literais (livros) e segmentos-variável, marcados com dois-pontos (:id).

match, linha a linha

Ela recebe um padrão e um caminho concreto, e devolve os parâmetros capturados — ou null quando não bate.

typescript
trecho ilustrativo
const patternParts = pattern.split("/").filter(Boolean);
const pathParts = path.split("/").filter(Boolean);

"/livros/".split("/") devolve ["", "livros", ""]: a barra inicial e a final produzem strings vazias. O .filter(Boolean) descarta tudo que é falsy, então sobra ["livros"]. Essa única chamada resolve de graça três casos que dariam bug — barra inicial, barra final e barras duplicadas.

typescript
trecho ilustrativo
if (patternParts.length !== pathParts.length) return null;

Saída barata, e é o que garante que /livros/:q (dois segmentos) nunca colida com /livros (um) nem com um futuro /livros/:isbn/edicoes (três). Sem essa linha, seria preciso inventar regras de precedência entre rotas — e num sistema onde POST /livros e GET /livros/:q dividem o mesmo prefixo, isso apareceria já na fase 10.

typescript
trecho ilustrativo
if (expected.startsWith(":")) {
  params[expected.slice(1)] = received; // ":id" vira a chave "id"
} else if (expected !== received) {
  return null; // literal que não bateu
}

Segmento com : captura o que veio; sem :, tem que ser igual. O slice(1) apenas corta os dois-pontos.

A sutileza que engana

match devolve null para "não bateu" e um objeto para "bateu" — inclusive {} quando a rota não tem parâmetro nenhum. Em JavaScript {} é truthy e null é falsy, então o if do laço distingue os dois casos:

typescript
trecho ilustrativo
const params = match(route.pattern, url.pathname);
if (params) return await route.handler(request, params);

Isso é frágil de um jeito instrutivo: trocar por if (params && Object.keys(params).length > 0) parece mais explícito e quebra a rota /, que casa com zero parâmetros.

Por que os !

O tsconfig do Bun liga noUncheckedIndexedAccess, então patternParts[i] tem tipo string | undefined mesmo dentro de um laço limitado por .length — o compilador não consegue provar que o índice é válido. O ! é você afirmando que sabe.

A rota descartável

/eco/:mensagem existe só para provarmos a captura de parâmetros antes de existir qualquer rota real com parâmetro. Ela some na fase 10.

src/index.ts — arquivo completo, com as mudanças marcadas

typescript
import { createDb } from "./db";

createDb();

type Handler = (
  request: Request,
  params: Record<string, string>,
) => Response | Promise<Response>;

type Route = { method: string; pattern: string; handler: Handler };

function match(pattern: string, path: string): Record<string, string> | null {
  const patternParts = pattern.split("/").filter(Boolean);
  const pathParts = path.split("/").filter(Boolean);

  if (patternParts.length !== pathParts.length) return null;

  const params: Record<string, string> = {};

  for (let i = 0; i < patternParts.length; i++) {
    const expected = patternParts[i]!;
    const received = pathParts[i]!;

    if (expected.startsWith(":")) {
      params[expected.slice(1)] = received;
    } else if (expected !== received) {
      return null;
    }
  }

  return params;
}

const routes: Route[] = [
  {
    method: "GET",
    pattern: "/",
    handler: () => Response.json({ message: "API da Biblioteca" }),
  },
  {
    // rota descartável: existe só para provarmos a captura de parâmetros.
    // Some na fase 10, quando a primeira rota de verdade com parâmetro chegar.
    method: "GET",
    pattern: "/eco/:mensagem",
    handler: (_request, params) => Response.json({ eco: params.mensagem }),
  },
];

const server = Bun.serve({
  port: 3000,

  async fetch(request) {
    const url = new URL(request.url);

    for (const route of routes) {
      if (route.method !== request.method) continue;

      const params = match(route.pattern, url.pathname);
      if (params) return await route.handler(request, params);
    }

    return Response.json({ error: "Recurso não encontrado" }, { status: 404 });
  },
});

console.log(`Servidor executando em http://localhost:${server.port}`);
