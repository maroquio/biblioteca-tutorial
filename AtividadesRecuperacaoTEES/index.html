Recuperação de arquitetura

Prepare seu fork no Windows, implemente duas tarefas em branches independentes e entregue dois pull requests.

Base: main · fase 5320 pontos no total120 minutos sugeridos

Como a entrega funciona

Você pode consultar o projeto e os quatro treinos. A lógica das operações está fornecida em blocos copiáveis; você identifica as responsabilidades, escolhe os arquivos, completa imports e integra a funcionalidade.

Trabalhe em um fork pessoal de maroquio/biblioteca-tutorial. Fork é sua cópia no GitHub; clone é a cópia desse fork no computador. Use um único fork e duas branches, ambas criadas a partir da main.

A recuperação só é considerada entregue quando você tiver criado dois PRs no repositório original: um para a 5B e outro para a 6B. Fazer commit ou push apenas no fork não conclui a entrega. Não é necessário que os PRs sejam mesclados para a entrega ser registrada.

1. Preparar o Windows

Use PowerShell no Windows Terminal ou no VS Code. Execute os comandos uma linha por vez; se houver erro, resolva-o antes de continuar. Os blocos não incluem o texto do prompt.

Tenha uma conta no GitHub e instale, caso necessário: Git para Windows, GitHub CLI (gh), Visual Studio Code e Bun para Windows. No instalador do VS Code, mantenha a opção de adicionar ao PATH. Feche e reabra o terminal depois das instalações.

PowerShell · Windows 
git --version
gh --version
code --version
bun --version

Se algum comando não for reconhecido, confira a instalação correspondente antes de seguir. No VS Code, você também pode abrir a pasta pelo menu File → Open Folder (Arquivo → Abrir Pasta) se code ainda não estiver disponível no terminal.

2. Entrar no GitHub e criar o fork

No PowerShell, autentique-se com sua própria conta. O primeiro comando apresenta um código e abre o navegador; conclua a autorização antes de executar os demais. Confira se o usuário mostrado é o seu.

PowerShell · Windows 
gh auth login --hostname github.com --git-protocol https --web
gh auth status
gh auth setup-git

Se ainda não tem um fork desse projeto, crie-o com o comando abaixo. Ele cria a cópia no GitHub; a clonagem será feita no próximo passo.

PowerShell · Windows 
gh repo fork maroquio/biblioteca-tutorial --clone=false --remote=false

Se já fez um fork na avaliação anterior, reutilize-o e pule esse comando. As branches da recuperação serão novas. Confirme no GitHub que o fork está em SEU_USUARIO/biblioteca-tutorial e indica que foi derivado de maroquio/biblioteca-tutorial.

Alternativa pelo site: entre no repositório original, clique em Fork → Create a new fork, escolha sua conta como Owner, mantenha o nome biblioteca-tutorial e confirme em Create fork. Escolha apenas uma forma de criar o fork. O login no terminal continua sendo usado para enviar suas branches.

Referências: fork pelo GitHub CLI e fork pelo site do GitHub.

3. Clonar seu fork e abrir no VS Code

Estes comandos criam a pasta de projetos no seu perfil do Windows. Quando solicitado, digite seu usuário do GitHub sem @. A pasta local biblioteca-recuperacao será criada pelo clone.

PowerShell · Windows 
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\Projetos" | Out-Null
Set-Location "$env:USERPROFILE\Projetos"
$usuarioGitHub = Read-Host "Seu usuario do GitHub (sem @)"
git clone "https://github.com/$usuarioGitHub/biblioteca-tutorial.git" biblioteca-recuperacao
Set-Location .\biblioteca-recuperacao
git remote add upstream https://github.com/maroquio/biblioteca-tutorial.git
git remote -v
code .

origin deve apontar para o seu fork; upstream, para o repositório do professor. Se a pasta local já existir e você estiver retomando esta recuperação, entre nela em vez de clonar novamente; não é necessário adicionar novamente um remoto já existente.

No VS Code, abra Terminal → New Terminal (Novo Terminal). Na seta ao lado do botão + do terminal, escolha Select Default Profile → PowerShell e abra um novo terminal. Execute os próximos comandos nesse terminal, na pasta que contém package.json.

Configure o autor dos commits neste repositório. Informe seu nome completo e um e-mail associado à sua conta do GitHub (pode ser o endereço noreply exibido em Settings → Emails).

PowerShell · Windows 
git config user.name (Read-Host "Seu nome completo")
git config user.email (Read-Host "Seu e-mail de commits no GitHub")

O comando code . abre a pasta atual como projeto; veja a documentação do VS Code no Windows.

4. Preparar a main usada como base

Faça isso antes de começar qualquer tarefa. Primeiro confira se não há alterações pendentes:

PowerShell · Windows 
git status --short

O comando deve ficar sem saída. Caso apareçam arquivos, salve e faça commit na branch à qual eles pertencem antes de trocar de branch. Não leve alterações de uma tarefa para a outra. Com o diretório de trabalho limpo, atualize a base a partir do repositório original:

PowerShell · Windows 
git switch main
git fetch upstream
git merge --ff-only upstream/main
git log -1 --format=%H

A base desta recuperação é a fase 53, commit 2da19331b3614bcfd7e890854986aa5721b0407f. Compare com o resultado do último comando. Se for diferente, ou o Git indicar divergência, peça ao professor para conferir a base antes de continuar. Isso também identifica um fork cuja main já contenha soluções anteriores.

Mantenha a main como base: não implemente as tarefas nela e não mescle a branch 5B nela antes de começar a 6B. Instale as dependências e prepare a pasta do banco local:

PowerShell · Windows 
bun install
New-Item -ItemType Directory -Force -Path .\data | Out-Null

Agora siga o enunciado de cada tarefa. A criação da branch é o primeiro passo em cada um deles. Se estiver retomando o trabalho em uma branch que já existe, use git switch recuperacao-5b ou git switch recuperacao-6b, conforme a tarefa, em vez de criá-la novamente.

5. Instalar e usar o Thunder Client

Faça os testes manuais da API com a extensão Thunder Client, dentro do VS Code. Cada enunciado traz seu roteiro de requisições e respostas esperadas.

  1. No VS Code, pressione Ctrl+Shift+X para abrir Extensions (Extensões).
  2. Pesquise Thunder Client, confira o identificador rangav.vscode-thunder-client e clique em Install. Você também pode usar a página oficial da extensão.
  3. Abra o Thunder Client pelo ícone de raio na barra lateral e clique em New Request.
  4. Selecione o método HTTP e informe a URL completa indicada no enunciado.
  5. Para POST ou PATCH, abra Body → JSON e cole o corpo fornecido. Na área de Headers da requisição, confira Content-Type: application/json. Para GET, deixe o corpo vazio.
  6. Com o servidor em execução, clique em Send. Confira o status HTTP, o JSON da resposta e, quando solicitado, os Headers da resposta.

Os comandos bun x tsc --noEmit, bun test e bun run verificar continuam como verificações complementares. Execute-os antes do roteiro manual: a suíte existente modifica o banco de desenvolvimento. Em seguida, prepare o banco e inicie a API conforme o enunciado. Não execute bun test no meio da sequência de requisições.

O Thunder Client envia as requisições; o servidor da biblioteca precisa permanecer executando no terminal. Se houver erro de conexão, confira a saída do servidor e a URL. Ao terminar os testes ou trocar de branch, encerre o servidor com Ctrl+C.

Referência: documentação oficial do Thunder Client.

5B — Corrigir ISBN de livro

Nova fatia no Acervo. 40 minutos sugeridos · 10 pontos · 8 blocos. Trabalhe na branch recuperacao-5b e abra seu primeiro PR.

6B — Registrar solicitação de empréstimo

Novo módulo com persistência própria e integração ao Acervo. 80 minutos sugeridos · 10 pontos · 11 blocos numerados. Volte à main, crie recuperacao-6b e abra outro PR.

  • O PR da 6B sai de SEU_USUARIO:recuperacao-6b para maroquio:main.
  • Os dois PRs estão criados, identificados com tarefa e nome completo, e cada um contém somente sua tarefa.
  • Informe na descrição de cada PR os cenários que executou no Thunder Client e os status observados.
  • Guarde os dois links dos PRs. Uma tela de comparação ainda não enviada não conta como PR.

Cada tarefa vale 10 pontos: localização (3), integração (3), fronteiras (1) e comportamento (3).
